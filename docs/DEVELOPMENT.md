## 2026-11-06：数据库修复优先，登记前端设计任务

用户要求先解释并解决数据库启动删表问题，再进行前端界面设计。本次先记录根因和任务顺序，没有修改 Go 运行逻辑。

### 数据库初始化：根因已确认，修复待实施

- `internal/infra/db.go` 的 `InitDB()` 在连接数据库后，无条件调用三次 `DropTable`，随后通过 `AutoMigrate` 重建表。
- `cmd/server/main.go` 和 `cmd/consumer/main.go` 都在启动时调用 `InitDB()`；正常启动、重启或新增实例都可能触发删除已有表及其数据。
- 问题是连接、表结构初始化和数据重置混在同一入口，没有环境判断或显式重置操作。现有提交历史没有说明最初编写删表代码的动机。
- 当前 Go 基线已包含该行为；仓库拆分只调整模块路径与文档，没有自动同步 Java 的修复。
- 修复目标：正常启动保留已有数据；结构迁移与测试数据重置采用独立、明确的执行入口。具体实现和验证结果在实施后记录。

### 后续任务：覆盖终端客户端全部功能的前端界面设计

状态：待数据库初始化修复后开展设计；尚未选择前端技术栈或实现页面。

以 `cmd/client/main.go` 为功能基准，设计至少覆盖：

- 连接配置：服务端端口、用户 ID、房间 ID；当前客户端连接本机，默认端口 `8080`、房间 `1001`，用户 ID 留空时自动生成，连接中的名称使用用户 ID。
- 连接状态与退出：连接中、连接成功、连接失败、服务端断开，以及主动关闭连接。
- 发送文本弹幕，接收并展示房间弹幕（协议类型 `101`）。
- 点赞操作：覆盖终端输入 `1` 触发的单次点赞（协议类型 `103`）。
- 展示服务端推送的在线连接数与点赞统计（协议类型 `102`）。
- 展示发送或接收错误，以及必要的操作反馈；当前客户端没有消息送达确认，不能把本地发送提示当作服务端确认。

本任务是为已有互动功能提供可视化界面，不包含音视频推流或播放器。保留终端客户端作为调试入口。Java 继续暂停，Go 测试、压测和基础设施启动仍按既有约束执行。
