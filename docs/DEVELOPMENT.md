## 2026-11-06：本机首次配置权限修复

用户运行入口时遇到 `SeSecurityPrivilege` 错误。用普通权限运行临时目录中的真实配置脚本，首次配置后再次执行，在受保护目录的 `Set-Acl` 调用处复现了同一错误。脚本进程仍存在也可能只是批处理在等待“按任意键继续”，不能据此判断正在等待配置输入。

回归脚本 `scripts/tests/setup-local.test.ps1` 在临时目录使用无业务意义的测试凭据，执行首次和重复配置，检查访问规则、加密格式与拒绝替换后的内容保留。本机 Windows PowerShell 5.1 和 PowerShell 7 均已通过。修复代码 `3b94826` 的 [Windows CI](https://github.com/JavaLyHn/DanmakuFlow/actions/runs/42243615063) 已通过两种 PowerShell 的真实脚本回归及现有模拟进程检查，[Go CI](https://github.com/JavaLyHn/DanmakuFlow/actions/runs/42243615085) 也通过。没有修改真实数据库连接、启动服务或请求用户在聊天中提供口令。

### 数据库初始化：修复内容

- 原基线的 `InitDB()` 将连接、三次 `DropTable` 和 `AutoMigrate` 放在同一入口；服务端和消费者的普通启动均会触发。仓库拆分保留了该历史行为，现有提交历史未说明最初的删表动机。
- 以 `OpenDB()` 取代旧入口，强制从 `DANMAKUFLOW_MYSQL_DSN` 读取配置；缺失、非法或没有数据库名的配置直接失败，不回退硬编码凭据。强制启用时间解析，连接、读、写超时默认各为 5 秒，可用 DSN 正时长覆盖。
- 服务端和消费者连接后先执行 `CheckSchema()`，通过 `SELECT ... LIMIT 0` 检查三张表的必需列。检查失败即退出，不进入 Redis、Kafka 或接收流量的初始化；数据库启动路径不执行 DDL 或数据写入。
- 新增独立 `cmd/migrate`，固定执行三条 `CREATE TABLE IF NOT EXISTS` 并检查结果，仅补建缺失表，新表使用 `utf8mb4`。不创建数据库、不改已有表、不提供数据重置命令；部分失败后可重跑补齐缺失表。
- 此检查不能证明字段类型、索引或额外必填列完全兼容，创建命令也不是完整版本迁移框架。已有结构变更需要单独审阅迁移。操作方法见 [数据库操作指南](DATABASE.md)。
