# DanmakuFlow 终端功能等价界面设计

状态：设计初稿，待用户确认。用户明确本轮只交付可预览设计和功能对照；确认后再实现。没有新增应用页面、后端接口或业务功能。

## 目标与范围

把 `cmd/client/main.go` 的现有交互转为可视化界面：配置连接、收发弹幕、点赞、查看房间统计，以及断开和错误反馈。协议、房间规则和身份语义保持现状。保留终端客户端；Java 暂停。

界面中的示例消息、18 个在线连接、126 次点赞仅用于设计展示，不代表实际数据。预览中所有点击都在本地模拟，不建立 WebSocket，也不连接 MySQL、Redis 或 Kafka。

## 布局方案

根据用户“视频未展示出来，更真实一点”的反馈，将单页调整为直播间布局：左侧主区域上方展示房间标题、互动连接状态和统计，下方为大幅 16:9 深色视频占位；紧凑的连接配置放在占位区下方。右侧展示房间弹幕、操作反馈和输入区，发送与点赞集中在底部。窄屏时上下排列，功能和内容不减少。

连接配置始终可见，连接后锁定；完整连接地址保留在配置区。布局调整只增加用户要求的静态视觉占位，不扩展业务能力。仍采用单房间、单页交互，不增加导航或连接向导，修订后的布局等待用户确认。

```text
DanmakuFlow · 房间互动
┌ 房间 1001 · 互动连接状态 · 在线连接 / 点赞数 ┬ 房间弹幕 ──────┐
│                                            │ 按接收顺序展示 │
│             16:9 深色视频占位              │                │
│             视频画面暂未显示               │                │
│             当前仅展示房间互动             │                │
│                                            │                │
├ 连接设置 ──────────────────────────────────┤ 操作反馈       │
│ 端口 / 房间 ID / 用户 ID       连接 / 断开  │ 单行输入       │
│ 完整连接地址                               │ 发送 / 点赞    │
└────────────────────────────────────────────┴────────────────┘
```

视觉使用简洁的蓝色主操作、清晰的文字层级和紧凑表单，以深色占位区形成直播间的主次关系。连接状态同时使用文字和颜色，明确表示房间互动连接；错误不只依赖颜色。没有虚构主播信息、侧边导航或额外业务统计。

视频区域固定显示“视频画面暂未显示”和“当前仅展示房间互动”，只是视觉占位，不包含真实视频元素、媒体源或播放能力。不显示播放/暂停、音量、全屏、清晰度等控件，也不显示“正在直播”“加载中”或“主播离线”等未经数据支持的直播状态。视频占位不随互动连接状态变化，不能将 WebSocket 连接成功解释为视频已接通。现有 11 种交互状态与协议语义保持不变。

## 连接与会话规则

- 连接前仅编辑端口、房间 ID、用户 ID；连接中及已连接时锁定配置。更换参数需要先结束当前会话，没有连接中切房功能。
- 用户 ID 是十进制 `uint64`，不是登录账户。当前终端自动生成 Unix 纳秒时间戳的十进制字符串；网页后续实现需保持数值范围和字符串精度，不能经 JavaScript `Number` 读取或存储大 ID。本轮预览使用演示 ID，不声称能提供真实纳秒时钟。
- 不改变服务端的参数语义：room 不能为空；UID 必须符合现有接口要求。错误反馈沿用连接失败的含义。
- 展示完整连接地址，包括 uid、name、room。后续真实 URL 需要编码参数，不能用预览字符串拼接代替实现。
- 主动断开或异常中断后，已经显示的消息和统计保留在当前画面；统计标为“上次接收，已停止更新”，发送与点赞停用。
- 结束会话后编辑连接配置时，主区域房间标题、已有消息和统计仍归属于上一次会话的房间快照；配置区地址标为“下次连接地址”。只有发起新连接时才切换会话房间并清空上一会话展示，不能把旧房间数据挂到新房间标题下。
- 再次连接是新的会话，清空上一会话的消息和统计展示，避免不同房间内容混在一起；旧终端输出本来也不属于新进程的会话状态。没有独立的清屏按钮或跨会话历史保存。

## 发送与接收规则

| 输入或事件 | 结果 |
| --- | --- |
| `你好` 后回车 | 提交文本弹幕 `你好` |
| `1` 后回车 | 提交一次点赞，不发送内容为 `1` 的弹幕 |
| ` 1`、`1 `、`01` 后回车 | 按原文提交弹幕，不能自动去除空格或转成数字 |
| 空行后回车 | 保留终端的空文本提交语义；不额外添加“不能为空”限制 |
| 点击点赞按钮 | 与输入 `1` 完全相同；保留输入框里尚未发送的文本 |
| 已执行本地发送 | 不显示“已送达/已读/服务器已确认”；自身消息也等房间广播后展示 |
| 收到房间弹幕 | 原样展示 content；可显示与终端日志类似的本地接收时间，不能称为服务端发送时间 |
| 收到房间统计 | 替换两个指标；更新不与某次点赞绑定，不据此生成点赞成功回执 |

当前客户端没有独立消息 ACK，也没有点赞 ACK。发送错误与本地操作反馈需要区分；不能照搬“发送失败后仍然输出已点赞”的误导含义。反馈仅表示本地发送动作被提交，失败时明确显示失败。

输入框为单行，不添加表情选择器、附件或多行编辑能力。emoji 作为普通文本仍可输入。界面不展示作者头像、昵称、消息 ID、已读标记或回复关系，因为当前终端不展示这些信息。

服务端统计通常约每 3 秒汇总推送，但不能展示保证精确更新的倒计时。弹幕和统计独立到达、独立展示：没有弹幕也可能已有统计，收到弹幕也不代表已有统计。首个统计包到达前显示 `—`，不能伪造为 0。在线数明确标为“在线连接”，不改称“独立观众人数”。消息展示保留前后及连续空格。

## 状态设计

| 状态 | 配置区/连接操作 | 消息区/指标 | 输入与反馈 |
| --- | --- | --- | --- |
| 未连接 | 可编辑；连接房间 | 空态；指标 `—` | 输入与点赞停用 |
| 连接中 | 锁定；按钮显示连接中 | 空态；指标 `—` | 显示正在建立连接；不重复发起连接 |
| 已连接、等待首包 | 锁定；可断开 | 等待第一条消息；指标 `—` | 可以提交弹幕和点赞 |
| 已连接、只有统计 | 锁定；可断开 | 消息空态；显示已接收的统计 | 正常发送和点赞 |
| 已连接、只有弹幕 | 锁定；可断开 | 显示已接收弹幕；指标仍为 `—` | 正常发送和点赞 |
| 已连接、已有数据 | 锁定；可断开 | 实际接收的消息与最新统计 | 正常发送；回车语义同终端 |
| 连接失败 | 可编辑；可再次连接 | 本次会话无数据；指标 `—` | 错误反馈；不自动重连 |
| 发送失败 | 连接状态以实际状态为准 | 不生成已发送消息或改动统计 | 显示错误；不自动重发，保留当前输入便于查看 |
| 主动断开 | 可编辑；连接房间 | 保留本次画面；统计标为上次接收 | 停用发送和点赞 |
| 接收失败/连接中断 | 可编辑；连接房间 | 保留本次画面；不再更新 | 显示中断原因；不自动重连 |
| 关闭操作失败 | 已结束会话，可再次连接 | 保留本次画面 | 关闭错误反馈；不暗示握手成功 |

预览的状态切换控件仅用于设计审阅，不属于未来产品界面的功能。示例消息不能进入真实运行界面的初始数据。

## 明确不增加的功能

登录注册、独立昵称或头像、任意服务器地址配置、房间发现/创建、多房间同时连接、自动重连、批量或取消点赞、视频播放器、主播管理、历史回放、消息搜索/筛选/清屏/导出、消息编辑/删除/回复、文件上传、送达回执，以及主题切换入口。

终端对无效消息封装和未知类型的现有忽略行为不新增为错误弹窗；重复的“Please input”日志转为常驻输入提示。终端标准输入 EOF 没有对应的网页业务操作，不增加文件导入或结束输入按钮。
